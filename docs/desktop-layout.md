# 桌面端页面布局

## 决策

桌面端保留 **Percho 的会话布局骨架和交互密度**，不增加额外顶栏、常驻右侧检查器或独立仪表盘壳。

2026-10-15 布局决策调整：Agent 模式在左侧栏内提供资源管理器、Chat、Git 三个工具入口，按需替换同一侧栏内容；这不是跨模式全局导航。右上角保留 `工作台 / Agent` 切换和新建会话操作，标题栏左侧不再显示 NextTools 品牌文字。

## 共用框架

```text
┌──────────────────────┬───────────────────────────────────────────┐
│ 左侧 Percho 风格栏   │ 右侧 Percho 风格主内容区                  │
│                      │                                           │
│                                            [工作台 / Agent] [操作] │
└──────────────────────┴───────────────────────────────────────────┘
```

模式切换只替换内容，不切换工作区、不清空会话、不停止运行中的 Agent。每个模式分别恢复该设备上一次打开的页面、选中项和滚动位置。

桌面宿主使用无边框窗口，并在原有顶部操作区域提供窗口拖动和菜单折叠；不增加第二条顶栏或常驻检查器。折叠状态按设备保存；菜单折叠时设置入口移至顶部，仍复用同一设置弹窗。Git 工具入口和侧栏面板只在 Agent 模式显示，只操作已授权工作区，并由 Rust Host 校验访问、审批和审计。

### 共用设置入口

- 设置按钮属于宿主共用框架，沿用 Percho 的设置入口位置，在工作台和 Agent 模式下始终可见；不受当前插件、有无页面或是否贡献主操作影响。
- 两个模式打开同一个宿主设置弹窗，复用同一组件、设置项和配置来源；不得各自维护一套工作台设置和 Agent 设置。
- 设置弹窗覆盖当前页面，不切换模式、不替换工作台/会话主内容容器、不停止 Agent。关闭后保留原页面、选中项和滚动状态。
- 全局快捷键等通用设置在任一模式中均可访问。插件可贡献设置项，但不能替换宿主设置入口或创建另一套全局设置弹窗。

## Agent 模式

- Chat 保留会话头、对话时间线、输入区和快捷键；侧栏按项目组织会话，不再额外放置独立会话列表。
- `项目`标题右侧的加号打开本地目录授权。每个项目可独立展开所属运行中与历史会话，项目右侧加号在该项目新建会话。展开项目同时选中它；工作台插件复用这个已授权工作区，不维护第二套选择。
- `智能体`入口管理本机模板的名称、描述、模型、系统指令和 Skills，支持新建、编辑、复制、删除和选择。模板选择仅影响后续新建或恢复会话，API Key 继续留在宿主系统凭据中。
- 右上角保留**新建会话**图标与语义。Git 入口位于 Agent 左侧工具区，工作台不显示入口或面板。
- `Pi Agent` 与其他对话插件可复用同一会话布局，但会话列表、模型设置和运行时状态按插件隔离。
- Agent 的工具调用、审批、Diff、产物和子 Agent 使用 Percho 风格的按需详情视图；不得为此新增常驻全局栏。

### 编辑器与 Git

- 资源管理器与工作台文件插件共用 CodeMirror 编辑器：语言识别、语法高亮、行号、折叠、括号匹配、缩进、撤销/重做、查找替换、跳转行、自动换行和保存快捷键。保存仍先展示 diff，再经 Host 单次审批，不直接写文件。
- Git 参照 CodingTo 的操作组织，提供暂存/撤销暂存、工作区和暂存区 diff、丢弃、提交、历史、分支创建/切换/合并、远端 fetch/pull/push、分支比较、Stash、混合/硬重置，以及冲突保留一方、完成或中止操作。
- Git 写操作使用五分钟单次审批；执行前重新校验工作区权限及仓库状态，拒绝、过期、重放和撤销均不能执行。Shell/Git 执行权始终在 Rust Host，不迁入前端。
- 参考：<https://github.com/ShimmerTo/CodingTo>；交互借鉴不改变 NextTools 的审批和能力边界。

## 工作台模式

首版工作台不另建布局：直接将 Percho 原有的**会话主内容容器**替换为 `WorkbenchHome`。其余 Percho 框架保持不变，后续工作台信息架构另行演进。

- `WorkbenchHome` 是工作台默认页面，展示可运行的插件和最近使用项；它不是新的仪表盘外壳。
- 有页面的插件从首页打开后，在同一个原会话主内容容器中运行；插件内部可使用自身页面布局，但不得包裹新的全局导航或移动宿主的右上角操作区。
- 无页面（headless）插件不占用主内容容器；它们通过命令面板、全局快捷键、自动化或 Agent 工具调用执行。
- 右上角原新建会话位置在工作台模式由当前页面插件贡献主操作，例如新建笔记、新建任务或新建文件。首页或无页面插件没有主操作时仅隐藏该主操作按钮，不显示占位；共用设置按钮仍可见。
- 从工作台回到 Agent 时恢复完整会话容器；从 Agent 回到工作台时恢复首页或该设备上一次打开的页面插件。

## Agent 与工作插件协作

Agent 参与工作插件的方式是受控工具调用，而不是在工作台页面常驻嵌入第二套聊天布局：

```text
Pi Agent -> tool.invoke -> Rust Host capability broker -> 工作插件 -> tool.result
```

工作插件可提供“以 Agent 打开”或“将当前选择作为上下文”等显式入口；进入后仍切换到完整的 Percho 风格 Agent 页面。这样保持页面专注，也不绕过审批、审计和能力策略。

## 实现约束

- 视觉和交互可参照/迁移 Percho React 页面，但不能运行其 Electron shell、preload 或 IPC。
- `apps/client` 用 Tauri/React 实现布局；Pi UI 与业务 UI 的状态通过 NextTools 协议获取。
- 宿主布局状态为设备本地偏好；会话、任务、产物和工作区数据按同步策略处理。
- 所有模式及插件操作必须支持键盘访问、可见焦点和移动端独立响应式布局。
