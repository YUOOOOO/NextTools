# 会话同步存储

> **翻译说明：** 本页是与 [英文源规格](/spec/03-runtime/23-conversation-sync) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

`@pi-desktop/conversation-sync` 存储账号的聊天文本，使多台设备可以收敛。它既不是 host-core 转录，也不是短暂的项目控制中继。

## 保存效果

`POST /v1/sync/changes` 接受 `{device, conversations, messages}`。

- 新会话、新消息、更新的标题或墓碑会取得下一个账号 `seq`。重复的已知消息 id 不会改变它。
- 超过 16,384 UTF-8 字节的文本会被裁剪且不拆分字符，并标记 `truncated`。
- 附件只存 `{name, mime, size}`。文件与图片被丢弃。最多保留 20 个附件。
- 每个账号只有一个 live `main` 会话。第二个会被 `main_exists` 与 `cid_main` 拒绝，其消息同样被拒绝。
- 新建侧会话超过 2,000 个 live 侧会话时，会被 `conversation_limit` 拒绝并留在设备上。
- 超过 20,000 条 live 消息后，最旧会话的消息会从中继中被丢弃。该请求写入的会话最后被裁剪。
- 关闭同步或调用 `DELETE /v1/sync/changes` 会删除已存会话与消息。seq 计数器保留。两者中只有关闭同步会同时停用开关。
- `DELETE /v1/sync/conversations/{cid}` 会把会话标记为墓碑并立即删除其文本。超过 30 天的墓碑在下次推送时移除。
- `POST /v1/sync/working` 只是在线状态。它只在内存中保留 10 分钟，不写入 SQLite。

`GET /v1/sync/changes?since=` 按 seq 顺序返回其后的变更。`since=0&tail=K` 返回最新 K 条消息、它们的会话行，以及 live main 会话，即使该会话的消息落在 tail 之外。

授权方式为 `Authorization: Bearer <token>`，映射到一个账号 id。

`POST /v1/auth/register` 与 `POST /v1/auth/login` 接受 `account` 或 `identifier`，外加 `password`。identifier 可以是 3–32 个字符的账号名、电子邮箱或中国大陆手机号。响应把同一份密钥同时作为 `token` 与 `api_key` 返回，`account` 为 `{id, channel, hint, member}`。`POST /v1/auth/code` 为邮箱或手机号记录一个六位验证码，但不发送短信。`POST /v1/auth/verify` 用该验证码换取会话。`POST /v1/auth/password` 修改密码，`POST /v1/auth/sign-out` 撤销 bearer 令牌，`DELETE /v1/me` 删除账号。`GET /v1/models` 返回 `{object:"list", data:[]}`。`GET /v1/me` 与 `GET /v1/me/profile` 返回已存资料；`PUT /v1/me/profile` 更新名称与外观。`POST /v1/chat/completions` 在未设置 `CONVERSATION_SYNC_UPSTREAM_KEY` 时返回 `503 upstream_unconfigured`。PI-Desktop 客户端使用 Node HTTP 访问所填服务器，而不是 Chromium 的 fetch，并接受不带 scheme 的 host:port。

`/v1/hub` 是一个 WebSocket。设备发送 `hello`，携带其 bearer `key` 与 `device.kind`（`phone`、`computer` 或 `web`）。`web` 设备可以发起 `call`，但不能被调用。hub 在账号内部转发 `call`、`result` 与 `event`，自身不执行动作。计算机与手机断开后仍留在 `hub_devices`。一次推送会用 `sync` 通知其它 socket。`GET /v1/devices` 列出已记住的设备；`DELETE` 遗忘离线设备，`PATCH` 重命名。桌面端以 `computer` 身份连接，接受 `info`、`sessions.list`、`chat.send`，以及远程动作 `shell`、`files`、`file.get`、`file.put`、`open` 与 `screen`。这些远程动作在执行前会询问电脑前的人。`chat.send` 会在该桌面上启动一个 Agent 回合。

桌面端从 设置 → 云同步 登录。访问令牌使用操作系统密钥存储加密。同步聊天会上传本地的用户与助手文本；工具行与流式助手检查点不会上传。串行的自动上传器在启动与登录时回填，Web 任务结束后请求一轮，并每 15 秒重试一次，使本地已完成的回合在 Host 持久化后也被包含。它在加载或上传转录前检查账号的同步开关，不重叠自动轮次，并在退出时停止调度。在登出或更换账号后，进行中的转录加载无法再上传。被拒绝的推送条目会成为可观测的失败，而不是成功状态。手动按钮保留。

Web 侧边栏列出云端会话，在连接时与收到 `sync` 通知时读取最多最新的 2,000 条已存消息，并提供显式刷新。选择一条会话会加载其受约束的云端历史，独立于浏览器本地任务历史；当执行器元数据可用时，还会启用同会话续聊。它不会导入或覆盖另一台桌面的 Host 转录。Web 任务结算会通知本地桌面会话列表。`/sync-view` 与主 Web 登录共享会话，并在收到 Hub 同步通知时刷新。未知令牌返回 `401 bad_key`。同步关闭期间的同步数据调用返回 `409 sync_off`；账号与 Hub 调用仍然可用。

## 多个 Web 会话

每台设备维护一组各自标识的 Web 会话。新建会话会生成新的任务会话 id 与空转录；选择列表中的条目会恢复其消息与实时的忙碌/停止状态。第一条用户消息为列表条目命名。消息、列表与当前选择按账号与设备持久化。既有的单会话历史会按需惰性迁移，且不删除其原始数据。任务回调在派发时捕获会话 id，因此切换视图不会把最终答案重定向或写到另一个会话下。停止只针对所选会话。运行中的会话不允许清空历史，且不会轮换其任务 id。桌面端桥接仍为每个调用方/会话持有独立的 Host 会话；Web 历史不会与只读的云端列表合并。

## 复用的云控制台

`/` 与 `/app/` 提供改造后的 nanoMuse 云用户控制台；`/app` 重定向到该处。静态资产与许可声明在本地与 Docker 构建中作为同一个目录交付，并采用可重新验证的缓存。`/sync-view` 保留早先的同步检查页面。S3 配置同步保持不变。

控制台选择一台设备并发送 `task {text, conversation, from}`。桌面端创建或复用专属会话，把权限模式设为 `ask`，并使用常规的 Agent 提示/中止准入。它转发安全的进度事件，并仅在获批的回合结束后返回 `{text}`。`stop {conversation}` 只取消该调用方自己的会话。socket 断开、账号更换或登出会取消工作并抑制过期结果。每个桌面安装持久化一个独立的设备 id；会话映射目前在进程内的 socket 重连之间保留，跨完整桌面重启则不保留。

`GET /v1/me` 包含真实的 `has_password`、创建时间与会话数。`GET /v1/me/sessions`、`DELETE /v1/me/sessions/{opaque-id}` 与 `POST /v1/auth/sign-out-all` 管理真实会话，绝不暴露 bearer 令牌。撤销会以 4001 关闭受影响的 live Hub socket。`GET /v1/me/events` 返回账号范围的活动，而不是聊天文本。增量的门户 schema 版本 1 保留既有密码与会话。Hub 接受控制台的 `forget {device_id}` 帧以遗忘离线设备。

该服务不宣传计费、邀请、训练贡献与移除密码。复用的页面用能力标志隐藏不受支持的控件，而不是展示虚构的用量或可用的开关。完整映射见该包内的 CONSOLE-COMPATIBILITY.md 与源码声明。

Web 任务进度在配置好其专属 Host 会话后包含 `stage: "session", sessionId`。浏览器把这一关联保存在其账号/设备会话条目上。云同步通知会把匹配的 Host 消息协调进空闲的 Web 会话，包括源自桌面的续聊。接受云端快照前，最后一条已完成的 Web 答案必须已经存在；这可以防止延迟上传抹掉尚未同步的回复。忙碌中的会话不会被替换。协调使用规范的云端消息，而不是追加重复项；关联关系在浏览器重新加载后仍保留。

`GET /v1/sync/conversations` 返回 bearer 账号的全部 live 会话元数据，独立于最近消息的 tail。因此空会话与较早的会话在 Web 云端列表中仍然可见。已删除会话被排除，账号同步开关同样被强制。桌面的 `session.list` 已包含项目会话；当前同步格式不携带项目分组与文件系统项目路径。

## 项目分组与续接云端会话

会话元数据可选包含 `project_id`、`project_name`、`execution_device` 与 `session_id`。桌面端对本地项目身份做哈希，只发送不透明 id 与 basename 显示标签，不发送完整的项目文件系统路径。分组身份为执行设备加项目 id；缺少项目元数据时显示为 全局会话。原生 Pi 与远程托管的会话不会被宣传为可执行的本地会话。

增量同步 schema 迁移记录版本 1，保留既有行，并在没有更新标题时间戳时也回填元数据。重复的元数据是幂等的；省略的旧字段保留已存值。执行元数据必须声明推送自身的设备，不能接管另一台设备的绑定。`GET /v1/sync/conversations/{cid}` 读取账号范围的 live 会话元数据与最多 500 条最新已存消息，独立于账号范围的消息 tail。

选择云端会话会使用常规聊天输入区。`task`/`stop` 携带其 cid 与 Host sessionId。Hub 在转发前校验确切的账号、会话、会话条目与执行设备绑定。桌面端还会确认该会话已成功共享给当前账号/服务器、仍然本地存在。它用原始项目、模型与模式恢复该确切会话，并使用常规 Agent 准入/中止与 ask 权限。未共享、缺失或远程的会话按失败关闭；缺少元数据会提示用户在原始桌面上同步一次。离线历史仍可阅读，但输入保持禁用，直到其执行器重新连接。未发送的输入区草稿在同步刷新后保留；并发的别名无法在同一个 Host 会话上运行两个任务。决策与权限边界见 ADR 0333。

## 桌面端的 Web 输入来源

来自 `web` 调用方的已认证 Hub 调用只会在被接受的持久用户行上标记可选的 `inputSource: "web"`。Main 通过对象身份保留这一准入标记；序列化的渲染进程、模型或调用方提供的字段都无法建立来源。该字段是显示元数据，不是模型提示文本，也不是权限依据。Host 转录元数据在读取/重开之间保留它。旧消息中缺少该字段的仍视为普通输入，不会被回填。桌面用户行会在气泡下方显示一枚简洁的本地化 “来自 web” 标记；本地用户消息与助手/工具行不显示来源标记。同一会话中混合来源的回合各自保留独立来源。旧的 `chat.send` 路径使用同样受信任的 Main 标记作为任务准入。

控制台侧边栏把品牌与账号卡片放在一个受约束、可用键盘聚焦的导航滚动区域之外。设备、Web 会话与项目/已同步会话列表在滚动时不会把账号卡片推出视野，包括在移动端侧边栏高度上限下也是如此。已同步的项目/全局分组只包含其 `execution_device`（或旧版设备回退值）与所选账号设备一致的行。选择另一台设备会清空旧的云端选择，保留其会话与草稿，并只显示新设备的分组。设备选择器会暴露按下状态并按账号记住所选设备；首次连接会要求用户选择设备。

## 交互式工具权限与 asktool 卡片

Web 控制台通过 `interactive.list` 读取所选在线会话当前的工具权限与 asktool 卡片，使用与共享任务续聊相同的 cid/session/device 绑定。共享会话中源自桌面的回合同样被包含。其递归轮询不会重叠列表请求，并忽略来自先前账号、选择与 socket 的响应。卡片状态是临时的，不是已存聊天消息；相同快照会保留表单输入与选择。

`interactive.resolve` 携带不透明卡片令牌，以及 allow-once/deny 或 answers 数组（每个问题一个字符串数组或 null）。桌面端会再次校验调用方、账号/服务器范围、会话、当前回合、确切待处理请求与存活后端，然后调用常规的权限/提问解析。其它标签页的令牌无法复用，并发请求共享同一解析锁。桌面端的决定会让卡片从下一次 Web 快照中移除；重复、过期或已终结的卡片按失败关闭。提问答案支持单选/多选、自定义文本与跳过/拒绝。预览会被脱敏并作为文本渲染；不提供永久授权。

这镜像了原始的 nanoMuse 审批往返，同时把 asktool 适配到 Pilot 自身的规范输入协议。计划/目标审批卡片、插件原生同意对话框与应用退出对话框不通过本协议转发。权威与生命周期决策见 ADR 0334。

被选中的提问选项以不透明选项标识符提交，并在桌面端映射回原始标签，与自定义文本分开。因此显示文本的脱敏或截断无法改变所选择的答案。卡片令牌保留其签发的 Host/sidecar 身份；在后端替换与 TTL 过期后，会在派发任何决定前于异步快照校验之后立即重新检查。

成功的本地会话/项目删除会把明确的会话 id 排入加密登录文件中按账号/服务器隔离的删除发件箱（仅 id）。下一次自动或手动同步会校验原始设备归属、提交云端会话墓碑、清空其文本并在上传 live 行之前通知对端。失败会跨重启保留队列；登出会丢弃该登录及其待处理队列。缺失或不完整的 Host 读取永远不会推断为删除。Web 会移除此前已知的已删除目录行、关联的本地浏览器历史、已选详情快照与卡片。其它设备的行永远不会被标记为墓碑。

对于修复前的孤儿行，只有拥有设备在显式调用当前 Host `session.get` 返回 null 后才能把清理入队。读取失败或未定义/不完整的响应不会确认删除。清理会由同一持久发件箱在下一个同步轮次重试。
