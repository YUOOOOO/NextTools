# 实施路线

## 依赖顺序

先实现可信本地 Host 和单设备完整闭环，再增加 Pi、账号、远控和同步。不要让服务端或移动端抢在本地权限边界之前决定执行行为。

## 当前落地状态

- 已有：Tauri/React/Rust workspace、SQLite 迁移、工作区选择与文件浏览、插件清单与启停、设备本地全局快捷键、Rust capability broker 和本地审计。
- 已有：固定 Percho submodule、可打包 Node runtime、Host↔Runner 协议、模型目录与系统凭据、会话创建/列出/恢复、流式事件、取消、工作区/Git/Shell 工具审批、Skills 和显式连接的 stdio/HTTP MCP。
- 已补齐：通用 `workspace-files` 创建、写入、删除和 unified diff；工作台文件页与 Agent 文件预览共用编辑器。仅允许工作区内 1 MiB 以内的 UTF-8 普通文件，写入先预览再单次审批，120 秒过期；执行时重新校验权限和原内容，并记录参数摘要及审批/执行审计。真实 Tauri 已验证创建、拒绝、批准写入和删除；Rust 回归覆盖冲突、过期、重放、插件撤销及跨工作区拒绝。
- 已补齐：Agent 项目展开与所属会话导航、本机智能体模板、CodeMirror 代码编辑器，以及受审批控制的 Git 暂存、提交、分支、远端、比较、Stash、重置和冲突处理。Git 回归覆盖本地远端发布/fetch/pull、分支检出、Stash 引用变化、合并冲突和审批拒绝/过期/重放/撤销/跨工作区绑定；真实桌面已验证 diff、暂存、拒绝和撤销暂存。
- 尚未达到阶段二完成标准：项目可信任、Pi extensions、subagents、完整 diff/待办体验，以及一次使用真实 provider 的端到端本地开发任务仍待验证。
- 待实现：当前 Agent 页面及整体布局向官方 WorkBuddy 的体验与布局方向调整，按 [桌面端页面布局](desktop-layout.md) 与 [UI 规范](UI_SPEC.md) 核对官方参考并验收。保留 Tauri/React/Rust Host 与 Pi Runner；本次文档更新不代表页面改造或多智能体能力已完成。
- 已实现自托管账号与远控链路：PostgreSQL 持久化、OIDC Authorization Code + PKCE、系统凭据库设备密钥、一次性配对、桌面项目/操作授权、加密会话快照和独立 WebSocket 控制中继。真实 Windows Tauri 与协议手机端已验证登录、配对确认、快照解密、控制到达 Host、越权/重放/过期/高风险审批拒绝、撤销及退出。尚未配置 Provider/API Key，未验证真实模型回复；不代表阶段三全部完成。
- 已接入移动端“工作台 / Agent / 我的”中的账号、设备、公钥确认、同步状态与远程会话界面，并保留独立 iOS 构建配置。浏览器仅验证移动布局；iOS Keychain、URI 回调、编译、签名、后台恢复及真机完整远控仍须在 macOS/Xcode 验证。Passkey、附件对象存储、推送唤醒、DeepSeek 与签名第三方插件仍未实现。

6. 按官方 WorkBuddy 参考调整 Agent 页面及整体布局，核对导航、会话、输入区和工具/产物详情；在真实桌面验证会话状态、后台执行、取消、审批与工作区隔离不退化。未核实的官方细节不预设为既定规范。

**完成标准：** 桌面端在不绕过 Host 权限边界的前提下，完成一次 Pi Agent 本地开发任务。

### WorkBuddy 方向专项开发计划

本计划以 Pi SDK 为 Agent 执行内核，在 NextTools 产品层实现面向 WorkBuddy 体验的任务闭环；不是复制其内部实现，也不预先承诺全部功能对等。以下均为待执行计划，不改变上文已有能力的落地状态。按 W0 → W1 → W2 → W3 → W4 顺序推进，每阶段验收后再进入下一阶段；W5 属于后续扩展，不能阻塞桌面单 Agent 闭环。

#### 架构与范围

- 保留 React → Rust Host → Node Runner → Pi SDK 链路；模型推理与工具循环由 Pi 承担，任务产品模型和调度策略由 NextTools 管理，不重写 SDK 推理循环。
- Agent 仍是插件，通过受控工具与 Event Bus 协作，不成为宿主架构中心。文件、Shell、Git、MCP、凭据、授权和审计由 Host 掌握；子 Agent 不获得父任务之外的隐式权限。
- 页面遵循 [桌面布局](desktop-layout.md) 与 [UI 规范](UI_SPEC.md)。Percho 保持固定版本与薄适配；Ace、Percho 仅作机制参考，官方 WorkBuddy 的公开资料和可实测行为才是对齐依据。
- 交付按用户路径和能力验收，不以页面相似、启动多个会话或生成任务列表代替功能完成。新增调度、任务状态和事件须先更新版本化契约，再实现 Host、Runner、UI。
- 本专项不迁入 Electron/Python runtime，不自动升级 Pi/Percho，不开发独立云端执行平台，不让手机本机执行 Node/Pi/Shell。

#### W0：官方参考与契约基线

**工作：**
1. 收集官方 WorkBuddy 页面与功能证据，记录 URL、日期/版本、截图状态和可复现操作；建立“官方行为 / NextTools 现状 / 目标 / 验收路径”对照，无法核实的条目标记待确认，不能由第三方项目补证。
2. 核对现有代码与文档，区分已有能力、未实现能力和仅缺验证的能力；优先验证真实 provider 下的文件读取、修改、执行与交付链路，避免重复建设。
3. 在 `docs/API_CONTRACT.md` 定义任务、执行尝试、工具事件、产物及父子任务关系的身份与生命周期，明确消息排序、错误、取消、审批归属和恢复语义；字段与方法名此时再定，不把本计划当成已存在 API。
4. 核对 `MANIFEST_SCHEMA.json` 的旧 `type/runtime/permissions` 与实际 `kind/capabilities/contributes` 差异，变更涉及插件声明前先统一契约；本地 SQLite 与 Supabase 快照分开设计，新增迁移，不直接执行或覆盖快照。

**交付：** 官方行为对照、能力缺口清单、经过评审的任务/事件契约与后续实施范围，写入现有布局、集成与契约文档。

**验收门槛：** 首轮目标均有来源与验收路径；未核实项不计入官方对等承诺；任务状态、会话状态和审批状态不混用。涉及云端前先裁定现有自建 WebSocket 文档与根指令 Supabase 约束的冲突，不沿用冲突设计扩建。

#### W1：桌面单 Agent 完整任务闭环

**依赖：** W0 的首轮范围与契约已确定。

**工作：**
1. 调整项目/会话导航、主内容、输入与按需详情，保留工作台切换、会话草稿、滚动和后台执行状态；具体位置按官方参考核对，不锁定旧 Percho 布局。
2. 将用户请求、模型处理、工具执行、等待审批、失败、取消和完成呈现为可追踪任务过程；计划与待办须反映实际执行，不生成虚假完成状态或无依据的进度百分比。
3. 串联文件、Shell、Git、Skills 和 MCP 的现有受控能力，明确展示工具参数、执行结果和审批原因。项目可信任策略单独建模，不能等同于永久批准全部操作。
4. 完善本次执行的 Diff 与产物审阅：范围绑定任务/执行尝试，展示真实文件差异与可打开的产物；不将工作区已有改动归为本次产出，不通过无条件 reset 实现撤销。
5. Pi Extension UI 仅在首轮范围确有依赖时启用；按 rpc 语义处理输入、确认、取消、超时和错误，不冒充终端 UI 或返回默认假成功。

**主要落点：** `apps/client/src` 的 Agent 页面与组件、`apps/client/src-tauri/src/agent*.rs`、`plugins/pi-agent/runner`，以及既有 Host 工具和协议；实现时按职责拆分，不继续向单个页面堆入调度逻辑。

**验收门槛：** 使用真实 provider 在临时授权工作区完成“提出任务 → 读取 → 审批修改 → 执行验证 → 审阅结果”；同时验证拒绝、停止、工具失败和切会话，后台消息/审批不串到前台，未批准操作没有副作用。真实 Tauri 截图与执行记录分别证明视觉和行为，不以浏览器预览代替 Host 验收。

#### W2：任务持久化与中断恢复

**依赖：** W1 闭环可用，任务与执行尝试身份稳定。

**工作：**
1. 为任务状态、执行尝试、计划、事件游标和产物引用增加本地存储与迁移；不复制完整会话历史形成第二套权威数据，不将 API Key、临时审批或大文件正文混入任务记录。
2. 定义 Runner 崩溃、Host 退出、断网、模型报错和用户停止后的状态转换；将“恢复历史”和“重新执行”分开，重启后不假装任务仍在运行或已成功。
3. 对有副作用的工具记录执行状态；结果不明时要求核查或人工确认，不自动重放 Shell、提交、删除等操作。旧 live 会话授权不得因恢复历史而复活。
4. 为重试创建独立执行尝试并保留前次结果；恢复 UI 从持久状态重建，不依赖仅存在于内存的通知或 Promise。

**主要落点：** `crates/local-store`、Host 任务领域与 Agent 生命周期、Runner 事件桥及任务恢复 UI；复用已有存储与协议机制。

**验收门槛：** 分别在模型输出中、审批等待中、工具执行中终止 Runner/应用并重启，任务显示真实中断状态、历史与产物可追溯，不重复执行副作用、不恢复过期授权；验证事件重放不重复显示结果。

#### W3：受控子 Agent 与并行编排

**依赖：** W2 可恢复任务状态已验收；先定义父子关系与工具契约，再实现并发。

**工作：**
1. 基于独立 Pi 会话运行子任务，明确父任务、拥有者、输入上下文、模型、工具权限、结果和生命周期；模板仅提供配置，不能充当调度器。
2. 实现创建、查询、等待、结果收集和停止子任务，并将完成/失败通知定向路由到所属父任务；前台切换与父任务暂时不在界面不影响结果归属。
3. 实现统一并发上限与队列，覆盖前台批次和后台任务；限制派生深度和资源占用，避免嵌套等待耗尽容量。依赖任务仅在前置成功时放行，失败后的继续或终止策略须显式定义。
4. 共享目录默认串行写入；首轮只并行只读任务或已隔离的工作目录。需要并行修改代码时另行实现隔离工作树与显式合并/冲突审阅，不能声称会话隔离等同文件隔离。
5. 父任务停止须传播到排队与运行子任务，等待在途工具达到可确认状态；停止不能回滚已发生副作用。子任务审批独立归属，权限不超过父任务与宿主授权的交集。

**主要落点：** Host 任务调度、Runner 会话适配、版本化协议与本地任务存储；不将调度器放在 React 组件或直接交给模型自主管理权限。

**验收门槛：** 运行两项并行只读任务并汇总结果，再验证队列饱和、嵌套派生、一个子任务失败、父任务取消、跨工作区拒绝及重启后的状态重建；后台结果不丢失、不串父任务、不超出统一并发限制。并行写入在隔离与冲突验收通过前不开放。

#### W4：协作视图与完整交付验收

**依赖：** W3 调度可用；展示只消费真实任务状态，不另建前端调度状态机。

**工作：**
1. 提供父子任务层级、状态、依赖、执行详情、审批入口及结果汇总；是否使用 Team、看板或其他形态由 W0 的官方对照与实际需求决定，不预设官方存在某种布局。
2. 提供从汇总到子任务、工具结果、Diff 与产物的追溯，明确失败、部分完成和未执行项；不将自然语言总结作为所有任务成功的证据。
3. 对照首轮官方行为清单逐项记录已对齐、差异、待核实和明确不做项，检查键盘访问、焦点、长输出、长会话和窄窗口下的可操作性。

**验收门槛：** 在真实桌面完成跨多个子任务的端到端开发任务，验证成功、部分失败、取消和恢复路径；产物可审阅、权限可解释、任务可追溯。只声明已实测范围，不使用“完全复刻 WorkBuddy”作为未经证明的结论。

#### W5：按需求扩展自动化与跨端

- 定时/触发任务：仅在需求与权限契约确认后实施；定义无人值守审批策略、错过触发、重复执行、时区与设备离线行为，不默认后台自动批准危险工具。
- 跨设备：复用已有配对与远控入口，先解决云端契约冲突，再按 Supabase 边界设计同步与恢复；手机仅查看/控制授权桌面任务，不执行本地 Node/Pi，也不动态加载原生插件。
- 新工具：浏览器、文档或其他领域能力通过 Manifest 声明的插件工具接入；逐项定义权限与实际产物验收，不以模型能描述操作代替可执行能力。
- 此阶段不是首轮桌面验收前置条件；每项需独立任务卡与验收，不默认纳入当前实现承诺。

#### 开发与交付规则

- 每阶段开始前输出任务卡，确认范围与影响文件后再实施；先完成当前阶段，不恢复或夹带已暂停的旧侧栏任务。
- 协议以 Rust 类型为源生成 TypeScript，不手改 generated 文件；新增状态变更同时更新契约与迁移，避免 UI、Host、Runner 各维护一套不一致语义。
- 实现验证执行前端 `npm run typecheck`、`apps/client/src-tauri` 下的 `cargo check`，并运行受影响行为的定向验证；Windows 打包路径验证 Node sidecar 与实际工具执行。
- 永久回归重点覆盖权限、跨会话路由、状态转换、取消、调度与副作用边界；真实 provider 的端到端记录与真实 Tauri 视觉验收不可由单元测试替代，凭据不入库、不入日志。
- 每阶段交付更新现有路线图、布局或集成文档，记录验收环境与未通过项；文档计划完成、编译通过或部分功能演示均不等于阶段开发完成。

## 每阶段验证

- 桌面：启动真实 Tauri 应用，执行对应用户路径。
- Rust：领域、存储、权限、签名和协议兼容性测试。
- Runner：流式、取消、崩溃、协议版本和工具结果测试。
- 移动：真机验证会话浏览、远控、后台/前台切换和推送唤醒。
- 安全：拒绝路径、过期请求、重放请求、撤销设备、越权插件和未批准操作。
