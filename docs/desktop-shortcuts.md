# 桌面端全局快捷键

## 决策

NextTools 的桌面插件可以贡献多个命令，**每条命令都可由用户单独分配一个全局快捷键**，不需要插件额外声明允许。命令以 `<pluginId>/<commandId>` 稳定标识；快捷键绑定命令，不是绑定整个插件或页面。

例如，用户把截图插件的 `com.nexttools.screenshot/capture` 绑定为 `F1`。Host 保存配置，下次启动时恢复注册；窗口失焦或隐藏后仍可触发。应用必须保持运行，完全退出后快捷键不生效；本设计不自动启用开机启动。

参考 [ZTools](https://github.com/ZToolsCenter/ZTools) 的一个插件多个功能入口、有页面/无页面交互模型；不迁入其 Electron shell、preload、IPC 或插件执行权限。

## 平台范围

[Tauri 2 Global Shortcut](https://v2.tauri.app/plugin/global-shortcut/) 文档列出 Windows、macOS、Linux 支持，不支持 iOS/Android。NextTools 只在桌面 Rust Host 初始化该插件；移动端不显示或注册全局绑定。实现验收必须覆盖实际桌面环境，不能仅凭平台列表保证所有键均可注册。

Tauri 默认不向前端开放全局快捷键权限。NextTools 不向插件 WebView 或插件前端授予 `global-shortcut` 的注册、批量注册、注销或批量注销权限；Rust Host 集中管理，设置 UI 只能请求 Host 修改用户绑定。

## 命令与页面

沿用 [插件系统](plugin-system.md) 的 `contributes.commands` 和 `contributes.views`，不建立第二套 manifest 协议。

```ts
type PluginCommand = {
  id: string; // 在插件内唯一，例如 "capture"
  title: string;
  description?: string;
  execution: "foreground" | "background";
  viewId?: string; // 引用本插件 contributes.views
  requiredCapabilities: Capability[];
};
```

- **有页面插件**：`contributes.views` 非空。命令可以关联 `viewId`，也可只执行功能、不打开页面。
- **无页面插件**：`views` 为空或省略，命令不关联 `viewId`。执行时保持当前工作台/Agent 页面，不为它创建空白页或聊天容器。
- 页面命令必须是 `foreground`；Host 打开或激活原 Percho 会话主内容容器内的插件页面。Pi 会话命令进入已有 Agent 模式。
- 无页面不等于完全没有临时交互：区域截图可显示受 Host 控制的选区浮层，授权和参数输入可使用宿主对话框，但不占用工作台主内容容器。
- 命令、视图和 Agent 工具是独立贡献；工具须显式贡献命令入口才能出现在快捷键设置中。

截图插件的命令贡献示例（非完整安装 manifest）：

```json
{
  "id": "com.nexttools.screenshot",
  "capabilities": ["screen.capture"],
  "contributes": {
    "views": [],
    "commands": [
      {
        "id": "capture",
        "title": "截图",
        "execution": "background",
        "requiredCapabilities": ["screen.capture"]
      },
      {
        "id": "capture-region",
        "title": "区域截图",
        "execution": "foreground",
        "requiredCapabilities": ["screen.capture"]
      }
    ]
  }
}
```

安装和更新不能将已有命令 ID 改为不同语义。删除命令时注销对应快捷键，保留不可用配置与原因供用户清理，不自动转绑到其他命令。

## 注册与执行链

```text
设备本地绑定 -> Rust Shortcut Registry -> 操作系统注册
操作系统按键事件 -> Host Command Dispatcher
  -> 命令可用性、调用上下文和能力检查
  -> capability broker、审批 -> 插件 runtime
  -> 结果或错误、审计
```

菜单、工作台入口、命令面板和全局快捷键走同一个命令分发入口。快捷键来源为当前桌面设备，不伪造远程来源或“已批准”。

- 启动时先加载本地绑定与已启用插件的命令目录，再逐条注册；单条失败不阻断应用或其他绑定。
- 启用/禁用插件、更新命令目录、修改/清除绑定时同步注册或注销；触发时仍检查命令存在、插件启用和平台兼容，避免注销期间的事件执行失效命令。
- 仅在按下沿触发一次，忽略释放事件和长按自动重复；同一命令正在执行或等待审批时不再从快捷键重复启动，不排队重放。
- 命令需要工作区、选中项或参数时，由 Host 解析明确的当前上下文；缺失时提示选择或填写，不能猜路径、套用失效会话或绕过审批。命令的必需能力必须是 manifest 已声明能力的子集。
- 有页面命令切换模式并激活页面，但不停止 Agent；无页面命令默认不聚焦主窗口。`foreground` 表示允许必要交互，不强制截图前切到 NextTools，从而改变截图目标。
- 已启动但没有打开页面的插件可按需激活其已授权 runtime，无需用户先从首页打开一次。不得因此启动未授权的进程或第三方原生代码。
- `background` 不代表免审批；所需权限未授权时，Host 提示用户授权或明确失败，不静默执行。系统权限、工作区策略和审计始终生效。

## 持久化与注册状态

```ts
type GlobalShortcutBinding = {
  deviceId: string;
  pluginId: string;
  commandId: string;
  accelerator: string; // Host 解析并按当前平台规范化
  enabled: boolean;
  updatedAt: string;
};
```

Rust Host 将绑定存入设备本地 SQLite 偏好设置，不进入工作区同步、实时控制请求或插件 manifest。每个命令至多一个绑定，规范化后的快捷键在本机只能对应一个命令；别名、修饰键顺序和平台键名按解析后的实际键组合检查，不能只比较字符串。

用户配置与实际注册状态分离：设置页分别展示“已注册 / 已停用 / 命令不可用 / 注册失败”和错误原因。不能因为配置为 `enabled` 就显示“可用”。每次启动重新注册，不能沿用上一次“注册成功”状态。

## 冲突、失败与生命周期

- **宿主保留键**：由 Host 维护显式的保留全局快捷键集合，和插件绑定一起检查；冲突时拒绝并显示用途。不默认把所有 Percho 页面内快捷键视为全局保留键。
- **插件间冲突**：保留原绑定，拒绝新的冲突配置，显示冲突插件和命令，不按注册顺序偷偷抢占。
- **系统保留或其他应用占用**：以实际 OS 注册结果为准；失败时显示系统返回的原因（未知原因不猜占用者），不偷偷换键或降级为页面内快捷键。
- **修改现有绑定**：先校验并尝试注册新键，成功且本地持久化完成后注销旧键；新注册失败时保留旧绑定。持久化失败则撤回新注册。启动恢复失败的已保存绑定保留配置并显示不可用，不能使其错误地覆盖当前有效绑定。
- **插件禁用、卸载、命令删除**：注销快捷键，保留不可用配置与原因，不触发自动重新安装。重新启用且原命令仍存在时恢复用户启用的绑定；用户清除绑定才删除配置。
- **应用生命周期**：窗口失焦、隐藏或关闭窗口但 Host 仍运行时保持注册；真正退出时统一注销。窗口关闭是否退出沿用客户端生命周期设置，不暗自引入托盘常驻。
- **单键 `F1`**：允许不含修饰键的功能键，不要求改成组合键；由用户明确启用并提示它可能截获其他应用的帮助键。笔记本可能需要 `Fn` 才产生实际 `F1` 事件，以系统收到的键为准，不承诺抢占系统保留键。
- **默认绑定**：不自动注册插件默认快捷键；插件可提供建议，只有用户明确保存才生效。全局绑定和 Percho 页面内快捷键分开管理，已被全局命令消费的按键不得在前台再重复执行同一入口。

## 设置与工作台入口

工作台与 Agent 均通过始终可见的宿主设置按钮打开同一个设置弹窗；“快捷键”是该共用弹窗中的设置页，不要求先切换到工作台，也不提供另一套 Agent 专属快捷键设置。

“设置 → 快捷键”按插件分组展示所有命令，支持搜索、录制、修改、清除及停用。无页面插件也必须可发现、可执行、可配置，不能因为没有视图而被过滤。录制时不执行该按键对应的命令，排除纯修饰键；此临时行为结束后恢复已注册绑定。

工作台首页和有页面插件的容器规则见 [桌面端页面布局](desktop-layout.md)。全局无页面命令执行不更改首页、当前插件、滚动位置或 Agent 会话。

## 实现验收

当前文档定义设计，以下是实现后的验收场景，不代表已实现或已通过运行验证：

1. 同一截图插件的两个命令可分别配置不同快捷键；将 `capture` 绑定为 `F1`，保存后重启应用，不先打开插件也能触发。
2. 主窗口失焦/隐藏时触发无页面命令，不跳转空白插件页、不重置当前 Agent；实际退出后不再响应。
3. 有页面命令打开或激活工作台容器中的对应页面，运行中的 Agent 不停止。
4. 同应用重复组合、别名等价组合、宿主保留键冲突均被拒绝；OS 注册失败显示错误。修改失败保留旧绑定，某条启动恢复失败不阻断其他命令。
5. 长按只启动一次，审批中不重复启动；快捷键录制不执行命令，结束后正常恢复。
6. 插件禁用/卸载/删除命令后不触发；重新启用恢复未清除的绑定；插件更新不能扩大能力或绕过审批。
7. 缺少工作区或参数时提示补全；未授予 `screen.capture` 或操作系统屏幕捕获权限时不偷偷截图。
8. 在 Windows、macOS 和实际 Linux 桌面环境分别验证，iOS/Android 不加载注册模块；绑定不通过账号同步到另一设备。
